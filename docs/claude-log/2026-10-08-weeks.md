### What changed

1. **One week rule.** `pipelines/nfl_week.py` defines both weeks:
   - `content_week`, which flips Tuesday and is used for every data label;
   - `game_week`, which flips Thursday and is used only where games matter (the weekly-dashboard
     check).

   These copies are gone: the Thursday-flip `_common.nfl_week`, `verify_import_health.WEEK1_START`,
   the `check_deadlines` anchor and the `check_weekly_freshness` anchor. Savers, pullers,
   `refresh_fantasycalc` and `pull_watchdog` default to the content week. The watchdog runs
   `make import-health` with no `NFL_WEEK`.

   `section_content_week` (the page's `sourceVintage` order) lives in the same module.
2. **VORP grain week = the source's content week.** This applies to the refresh, the checkpoint,
   the `translate_document` provenance and the monitor check.
3. **CBS versioned bakes.** Migration `supabase/migrations/cbs_bakes_source_urls_20261008.sql`.
   - Bake ids are `cbswk<N>_<YYYY-MM-DD>t<HHMM>_v1`. USA Today got the same minute stamp
     (USAT-BAKE-SAMEDAY).
   - The same-week guard compares against the latest bake. This also fixes USA Today's guard,
     which blended a week's bakes.
4. **History.**
   - Every saved bake in the base tables is a version.
   - One snapshot per source and week, chosen by the rule:
     - articles: the latest revision before the week freezes;
     - FantasyCalc: the first pull at or after Tuesday 12:00 UTC;
     - projections: the newest snapshot dated in the week.
   - The other versions go to `data/history/superseded/`, which is not served.
   - The index matches a served superseded version.
   - Prior weeks now exist for:
     - ESPN: the pipeline leg rebuilt from saved `espn_ppg`, served as
       `assets/history/espn-legs.json`;
     - the VORP vs waivers series;
     - the Adjusted series, priced through the current fit.
   - ESPN entries keep ESPN's projects-0 players as `[0,0,0]`.
5. **Source URLs.** Savers write `source_url`. The importer, then `source_provenance`, then
   promotion carry it to `sources.<key>.url`. The migration backfills the served weeks' URLs.
6. **Freshness.** `reference-freshness.json` has a published/saved content-week row per source,
   and the summary names the oldest published week, the sources behind and the sources pending
   promotion. `built_at` is relabelled. Nothing new is enforced.

Docs: `docs/v2-design-notes.md` "Which snapshot is a source's week" and the history contract
(ESPN, VORP, Adjusted, superseded, `served.version`); `docs/methodology.md` "Week-Over-Week
Snapshots"; runbook `weekly-dashboard-freshness.md`.
