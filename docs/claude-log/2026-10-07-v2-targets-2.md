### Why rule (b) is "our value > 0" and not the ESPN tier
Every series compared here is value above waivers for the user's league. Our
own waiver line is therefore our value = 0, or no value at all.
- CBS rest-of-season and Razzball put 0 on every player their roster model
  (teams x roster) calls waiver.
- The ESPN line prices only its rostered pool and gives everyone else no value.
A buy needs ours > chart > 0, so "outside our rosterable pool" can never be a
buy. The engine also exposes a tier (`espnRole`), but that tier comes from a
different roster model than the ESPN line. At full PPR, 12 teams, 25 players
tiered Waiver have a positive ESPN value (Blake Corum 7.2, rank 107 of 176).
Filtering on the tier would have hidden players whose displayed value says they
are rostered. That mismatch is logged as V2-TIER-VS-ESPN-LEG.

### Waiver-line finding (what sets 0 on a published chart)
- **The rule, at every setting.** 0 = at or below the waiver line of
  `translatePublishedVorp` (value-model.js), which is a port of
  `unified.translate_ranked`. At each position the line is the native value of
  the player at rank n_rostered, where n_rostered = teams x slot + flex share +
  bench share. The bench share is apportioned from the 12-team bench mix.
  - Derived settings (any setting other than 12 teams on the standard roster)
    run this in the browser (`derivePublishedSetup`, league-settings-001/3).
  - The saved setup (12 teams, standard roster) shows saved values. The server
    ran the same translation on each combo's own natives
    (`translate_via_vorp.apply_combo` with `unified.translate_natives`,
    JEG332-STORED-DRIFT).
- **Saved-setup zeros are rosterable-count zeros, not chart-length zeros.** In
  the fixture, all 12 saved 12-team combos (4 charts x 3 scorings) show
  vorp-supabase / combo-natives, `n_fallback_reindex` 0 and `n_below_waiver`
  13-90. In the browser at 12 teams, each chart's set of players at 0 equals the
  set the translation puts at or below the line at that setting: 0 mismatches
  each way for all four charts. The same holds at 10 and 14 teams. So the fail-safe
  values that JEG332-BELOW-WAIVER-SAVED described are gone from main.
- **The exception: chart length decides when a chart is short.** If a chart
  lists fewer players at a position than the league rosters, the line falls back
  to the chart's last listed value (`insufficient_coverage`). The bottom of that
  chart is then 0 because the list ended. Full PPR, listed / rostered:

  | Chart | Teams | Short positions (listed / rostered) |
  | --- | --- | --- |
  | CBS | 12 | QB 12/21, RB 43/57, WR 44/69, TE 17/21 |
  | CBS | 10 and 14 | all four positions |
  | FantasyPros | 12 | RB 51/54, TE 20/21 |
  | FantasyPros | 14 | RB, WR and TE |
  | FantasyCalc | 14 | RB 60/65, WR 76/83 |

  Example: CBS full/12 gives 0 to Ollie Gordon II and Zach Charbonnet (its RB
  35-36, ESPN tier Starter) and to Matthew Stafford (its QB12). This is engine
  math, so it was not changed here: proposed fix in risk row V2-WAIVER-COVERAGE.
  The tab already keeps these players off the buy list.
- **Publisher floors.** FantasyPros gives 23 players its floor value of 1.0,
  including every QB from its QB14 (Kyler Murray, Jayden Daniels) down. The
  roster-determined line falls on that floor, so all of them are 0. That is the
  publisher's own valuation, not chart length.
