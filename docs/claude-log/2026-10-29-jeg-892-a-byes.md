## 2026-10-29 - Bye week on player rows, path A: byes only (JEG-892)

Contract: one of two draft paths built on Jeremy's instruction (Oct 29: "If we need a decision but there are only two
real Paths, do the work for both, and then we'll decide after"). Path A adds each player's bye week to the player rows
in Compare a trade, Find a trade and Trade targets. No injury status, no filter, no value changes.

What changed:
- `app/v2/player-flags.js` (new): `teamCode` (JAC/LAR/WSH/LVR to the bye table's JAX/LA/WAS/LV), `byeOf`, `byeText`,
  `node`. The bye comes from `window.TradeValueByes` (nfl-byes.js, built from `data/inputs/nfl_byes_2026.json`, the
  same table the pipelines and the Waivers tab use). A free agent or unknown team gets no bye. "(done)" and "this week"
  need the calendar week from source freshness; without it the row shows the week alone. Hover names the source.
- `app/v2/v2.js`: Trade targets (table and phone cards) and Compare rows put the bye between team and tier, so the tier
  stays the sub-line's last part (render tests read it there).
- `app/v2/finder.js`: roster rows, the target line and the package pick rows.
- `pipelines/build_v2_page.py`: loads and ships `player-flags.js`.
- `Makefile`: `tests.test_player_flags` in test-core and test-core-shard-3.
