## 2026-10-26 - JEG-1154 phone 320 px: the League "Overall fit:" filter no longer scrolls the page sideways

Contract: at a 320 px phone width the League page scrolled sideways by ~15 px
because the `#v2LgFilterFit` select is as wide as its longest option ("Natural
and market supported"). Make the filter row shrink it (CSS only) and add a
render guard that names the select.

### Verified (check named)

- `python3 -m pytest tests/test_v2_league_phone_render.py -q` -> `2 passed`
  (both tests: the checks, and `test_guard_fails_on_broken_builds`).
- Root cause measured before the fix with the league render harness at 320 px
  (scratch script, `tests/_league_render.browser_on_build` + `seed("4team")`):
  `documentElement.scrollWidth` 335 vs `clientWidth` 320; the only boxes past
  the right edge were `SELECT#v2LgFilterFit` (right 335) and its `.v2-field`
  label (right 335), inside `.v2-lg-filters` (254 px wide).
- After the fix, same harness at 320/360/390/1366: `scrollWidth == clientWidth`
  at every width; the fit select is 192 px at 320, 232 px at 360, 240 px at 390;
  the desktop layout is unchanged (`#v2LgFilterFit` at x 329-631 with the five
  fields on one line at 1366, same as before the change).
- Guard proved on a broken state: with the two new `.v2-lg-filters` rules
  temporarily removed from `app/v2/v2.css`, `pytest ... -k test_phone_contrast_keyboard`
  failed with `'[320px fit] #v2LgFilterFit runs to 335px on a 320px phone'`,
  `'[320px fit] the #v2LgFilterFit label runs to 335px on a 320px phone'` and
  `'[320px fit] the page is 15px wider than a 320px phone with #v2LgFilterFit on it'`;
  the CSS was restored from a copy (`git diff` shows only the intended 4 added
  lines in `app/v2/v2.css` afterwards, and the test passes again).
  The same revert is pinned in the test file as the mutation
  "the fit filter is wider than a 320 px phone", which runs only the new
  `fit-filter` check, so the guard is proved without a manual step in future runs.
- `python3 -m pytest tests/test_v2_league_top10_render.py -q` -> `2 passed`
  (it drives `page.select_option("#v2LgFilterFit", "natural")`; the narrower
  select still drives the filter).
- The unchanged generic overflow check and the 44 px control check in
  `check_phone` still pass at 390/360/320 px, so the select is neither hidden
  nor shrunk below the tap-target floor.
