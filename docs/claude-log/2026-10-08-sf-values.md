Builds on the superflex roster slot (docs/claude-log/2026-10-08-superflex.md),

when the roster has a superflex slot. Risk register

### What changed
- **Producers** (each writes `qb_slots = 2` rows in the same bake as the 1-QB
  rows, `native_value` = the published number):
  - FantasyCalc: `pull_fantasycalc_12team.py` also pulls `numQbs=2` (12 teams,
    three scorings) into `fantasycalc_<scoring>_12_qb2.json`; a 2-QB list that
    fails the size checks is skipped with a warning and never holds the 1-QB
    save. `save_fantasycalc_references.py` saves them (every position, `value`
    NULL) when all three are cached.
  - CBS: `save_espn_cbs_references.build_cbs_rows` saves the QB table's "2QB"
    column (QB only, reused for the three scorings, value = native). A QB
    dashed in the 1QB columns but priced in 2QB keeps his 2QB rows.
  - USA Today: `save_usatoday_references.parse_superflex` reads the QB table's
    SFLEX column (QB only, three scorings, `value` NULL).
  - FantasyPros: `pull_fantasypros.parse_superflex` reads "2QB Value" (QB
    table only, never the TE table's TEP column) into the CSV's `value_2qb`;
    `save_fantasypros_references.py` saves it (QB only, three scorings,
    `value` NULL). `--save` re-saves a week that was saved without 2QB rows
    when the chart has the column (otherwise Week 5 would wait for Week 6).
  - The shared isotonic reindex (`apply_reindex`) passes qb_slots = 2 rows
    through with `value` NULL; `build_reindex_candidate` still fails closed on
    any other qb_slots.
- **Importer** (`import_supabase_references.py`): splits qb_slots in Python
  (NULL = 1). Only 1-QB rows choose the week and bake and fill `rows`; the
  qb_slots = 2 rows of that same week and bake ride along as
  `superflex_rows` / `superflex_review_rows`, priced by `native_value`. A
  snapshot without superflex rows has no new keys (byte-identical).
- **Chain**: `match_source_snapshot` matches them with the same identity rule
  (`superflex_matched_rows`); `build_source_reference` attaches them to the
  1-QB artifact of the same (scoring, teams); `build_comparison_source_section`
  writes `native_superflex` (slug -> value, fixture identity only) on that
  combo (`_qb1` for FantasyCalc); `reindex_comparison_section` copies it
  untouched; `promote_comparison_section` validates it (identity, >= 0) and
  replaces it with the natives, removing it when the new publication has none.
  `native`, `player_keys` and the 1-QB review rows never see superflex rows.
- **Readers**: `verify_import_health` and `check_source_vintage` read
  `qb_slots=eq.1`; the same-week ingest guards (`ingest_common.grain_key`,
  used by ingest_usatoday / ingest_cbs) key rows by qb_slots.
- **Python reference**: `unified.load_native_values(superflex=)` and the
  test reference (`browser_inputs` / `browser_peers` / `expected_derived`)
  overlay `native_superflex` with the slot, as the browser does. Without this,
  the first fixture carrying superflex values turned `make validate` red
  (below).
- Docs: methodology "Superflex" (how they are saved), math review agenda
  MR-15 (and MR-02's sub-question), risk register row.
- No migration: both tables already carry qb_slots in their unique grains
  (`source_trade_values_bake_version_uidx`, `cbs_trade_values_grain_uidx`),
  `value` is nullable, and `api.source_inputs_weekly` / `v_source_trade_values_wide`
  already filter qb_slots = 1. `api.source_freshness.latest_week_rows` will count
  the extra rows (informational; week and dates unaffected).
