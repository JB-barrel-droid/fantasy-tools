## 2026-10-28 - Buy/Sell suppressed for a thin DDF Value (JEG-1186)

Contract: Jeremy, 2026-10-27 ("Suppress"): a player whose DDF Value is backed by fewer than 2 sources gets no Buy or Sell call, and the Trade targets page says why. This replaces the 2026-10-08 rule that a one-source DDF Value is still a target (shown flagged).

Changes: `app/v2/targets.js` (`MIN_DDF_SOURCES = 2`, `thinSupport`: reads `ddfCount` for ddf_value, `ddfChartsCount` / `ddfProjectionsCount` for the two versions; a single published series as our value is never thin, an unknown count is never thin; `buildTargets` returns `thinSource` / `thinSourceNames`). `app/v2/v2.js`: the notes get "N player(s) left off Buy and Sell: only 1 source backs his/their DDF Value (names). A Buy or Sell call needs at least 2." `tests/test_v2_targets.py`: the 2026-10-08 assertion ("a one-source DDF Value must still be a target") and the "one-source player left out" mutation were replaced, because Jeremy changed the rule on 2026-10-27, not because the code was bent to pass. The contract test's TT-08 check and its mutation, and the TT-08 line in `docs/feature-contract.md`, were changed by the lead for the same reason. New: `tests/test_v2_targets_thin_render.py`, added to `make test-unit` next to `tests.test_v2_targets_render`.

### Verified (check named)
- `RENDER_TESTS_REQUIRED=1 python3 -m unittest tests.test_v2_targets_thin_render`: both tests pass. The render test injects two synthetic players as data into a temp copy of the build (comparison-sources-data.json and the engine page's player rows; no code stubbed): a 1-source player (ddfProjectionsCount 1) and a 2-source twin, with identical chart values. It asserts in the page that both arrived with the intended counts and numbers, and that the real `buildTargets` on a copy of the rows with the thin player's count set to 2 lists him as a Sell. Then: the 1-source player is in neither list (engine lists and drawn rows), the twin is a Sell row, the notes carry the "left off Buy and Sell: only 1 source" line naming him and not the twin, at 1366x768 and 390x844, no page errors.
- Same file, `test_guard_fails_on_broken_builds`: `thinSupport` always false, the v2.js note removed, and `MIN_DDF_SOURCES = 3` each make the render checks fail.
- The render checks run against `origin/main`'s `targets.js` and `v2.js` (before the change) report 10 errors (1-source player listed as Sell, no note), so the test fails without the change.
- `python3 -m unittest tests.test_v2_targets tests.test_validate_shards`: 16 tests pass.
- Why the render test uses the DDF Value (projections) version: on the default DDF Value every real row has ddfCount 3 (the blend's sources are the compared charts, and a chart that does not list a player prices him at 0, which still counts), so data alone cannot make it thin while 2+ charts price the player. ddfProjectionsCount is really 1 or 2 for many players, and the Our value picker offers that version.
