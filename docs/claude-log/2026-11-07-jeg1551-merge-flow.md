## 2026-11-07 - JEG-1551 merge flow: known-good test data, review receipt, merge queue

Contract: stop one bad data rebuild from turning every open PR red, and let a
green PR with an independent review merge itself through the merge queue, with
Jeremy's yes kept for value math, migrations and deploys (Jeremy, 2026-11-06,
picked A).

### Verified (check named)
- PR and merge-queue builds restore the bot-written data paths from the newest
  main commit whose `v2 render test` push run passed, and leave paths the PR
  itself edits alone: `tests.test_jeg1551_merge_flow.DataPinTest`, including a
  real temporary git repo run of `ci_data_pin.apply`.
- Any doubt (no token, API error, a file list that may be cut off, a pin that
  cannot be fetched) leaves the checkout as it is: same test class.
- `preview` and `v2-render` no longer use a `paths` filter, so they always
  report; a docs-only PR passes them through `pipelines/ci_change_scope.py`
  without the heavy build: `tests.test_ci_speedup_workflows` (scope_problems
  and `test_docs_only_check_that_never_reports_is_caught`) and
  `tests.test_jeg1551_merge_flow.ChangeScopeTest`.
- The preview build still matches the Pages build apart from the pin step,
  and dropping the pin or moving it after the build is caught:
  `tests.test_preview_workflow_matches_pages`.
- `review-receipt` passes only on a non-draft PR whose latest `ddf-review`
  verdict is PASS on the current head (or an older head with an identical net
  change), fails on a later FAIL, needs `jeremy-approved` for value math or a
  migration and `handoff-edit` for HANDOFF.md, and fails closed on API doubt:
  `tests.test_jeg1551_merge_flow.ReviewReceiptTest`.
- `review-receipt.yml` is listed in `config/monitoring_coverage.json`:
  `tests.test_monitoring_coverage` no longer names it. That test still fails
  on chain-run-feedback.yml, main-write-pause-switch.yml and
  main-writer-checks.yml, which fail the same way on main.
