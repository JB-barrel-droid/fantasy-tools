### Findings and fixes

- **Fixed: the PR reverted three pieces of main's MCP edge function** (commit a1f95a4b, built from a stale base).
  None of them is part of the viability rule. Restored `supabase/functions/mcp/index.ts`, `find-trades.ts` and
  `tools.ts` to origin/main:
  - `index.ts` loaded finder.js with a bare eval again. finder.js throws "document is not defined" after it
    publishes `TradeValueFinder`; the throw went to the catch, `finder` stayed null, and `find_trades` would have
    said it is unavailable in production (the #903 / JEG-1037 bug).
  - `index.ts` dropped `CACHE_MAX`, so the league-keyed values cache grew without bound.
  - `tools.ts` `explain methodology` went back to the pre-#919 text ("projection sources and trade charts are
    blended"), which is wrong since JEG-1073 (DDF Value is the average of the four adjusted trade charts).
  - New `tests/test_mcp_finder_loader.py` pins all three; it fails 3/3 on e40f2832's files and passes on the fix.
- **Fixed: the find-trade impact panel showed `ddf_value_charts` under the "Trade chart average" label.** The PR
  had dropped `withChartAverage` from `lineupContext` and pointed `viewKey` at MARKET_KEY, so "You: best starting
  lineup ... Trade chart average 306.9 -> 319.4" while the chart mean of the same rows was 219.3 -> 226.7
  (`tests/test_v2_finder_impact_render.py::test_roster_impact`, 36 mismatches). Restored main's `lineupContext`
  (rows keep the engine's `ddf_value_charts` and gain `chart_avg`) and set `viewKey` to CHART_AVG_KEY. The fit tier
  and viability label still read MARKET_KEY = `ddf_value_charts` from the same rows, so the rule is unchanged.
- Stale comments updated: `viability.ts` header (their side is `ddf_value_charts`, not the chart mean) and the
  `fitFor` comment in `finder.js` (lineup.*.market are engine rows carrying `ddf_value_charts`).
- Correction to the DeepSeek entry (2026-10-26-jeg1129-chart-avg-key.md): its `balanceCounts` row says the callers
  pass rows through `withChartAverage`. They do not (site: raw `rowsOf`; MCP: `toFinderRow`), so the literal
  `"chart_avg"` there never matches and a throw-in from their roster is chosen by `ourKey`. Same as on main; not
  changed here (question to Jeremy on the PR).
