## 2026-10-26 - Overrides: an adjustment kind and a flag on every overridden value (JEG-1058, JEG-1059)

Contract: a reader's player override is either an absolute value or an
adjustment to the pipeline's own DDF Value, and every place an overridden
DDF Value shows carries a badge that says so.

### Verified (check named)

- `python3 -m unittest tests.test_basis_overrides` — 42 tests OK. The new
  `AdjustmentOverrides` group covers the adjustment in all three engines
  (JS, Python reference, spec reference), a negative delta, the 0-100 cap, an
  adjustment on a player nobody prices (the delta is the value), and an
  adjustment that survives a basis switch.
- `python3 -m unittest tests.test_value_overrides` — 2 tests OK. The new case
  drives the engine overlay: `+5`/`-3` add to the pipeline value, the value
  caps at 100 and 0, `row.valueOverrideSpec` carries the kind, the pipeline
  value on the row does not move, and an invalid delta is refused.
- `python3 -m unittest tests.test_v2_override_adjustments_render` — 10 tests
  OK (Playwright, local Chrome via `CHROMIUM_PATH`). The reader's path is
  driven: search a player, switch the kind, type the value. It pins the
  absolute-by-default toggle, the adjustment's value and caps, the saved
  record in localStorage, the share parameter `ov=key:+5`, a link that reaches
  the reader as an adjustment, the export/import file, the badge and its
  tooltip in Player values, the "Your override" build-up note in the player
  panel, and the badge in the Overrides tab's own list.
- `CHROMIUM_PATH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" make sync`
  — the build succeeds and the values explainer renders (it needs a browser;
  the system Playwright has no Chromium of its own).
- `make validate` — the deploy gate passes (build plus `make test-core`).

### Claimed, not confirmed

- The badge appears on every surface the spec names (Player values, Trade
  targets, Compare a trade, Find a trade, Waivers, the workspace opportunities
  table, the Overrides tab). The render test pins the Player values cell, the
  player panel and the Overrides list; the other surfaces were checked by
  reading the code (`app/v2/v2.js`, `app/v2/finder.js`, `app/v2/waivers.js`,
  `app/v2/league.js`), not by a test on each screen.
- The share link carries an adjustment as `ov=key:+5`. `URLSearchParams`
  decodes `+` as a space, so the reader's link is parsed with a leading
  whitespace read as a sign. Checked by the render test above; the packed
  `z2:` form is checked by the unit tests.
- Nothing is published: no deploy, no merge. The explainer's math-review
  banner was refreshed with `make values-explainer MARK_REVIEWED=1` after the
  narrative was updated.
