## Jeremy's definitions (2026-10-28) against the code

- **DDF Value = the average of the weight-adjusted indexed values, not the
  trade chart average.** Matches main. The code averages the charts' Adjusted
  values (VP-5, VP-6.3). Adjusted values ignore a chart's scale (VP-5.5), so
  re-running the pipeline on the Indexed (rescaled) values gives the same
  Adjusted values and DDF Value (post04.json `ddf_value_vs_rescaled`: max
  difference about 1e-13). DDF Value is not the plain mean of the rescaled
  charts, the "trade chart average" Compare uses as the market (median gap 2.8,
  max 18.2 for rostered players). The posts now say this in these terms.
- **DDF Value (projections) = the average of the imputed values across
  projected sources.** Does not match main if "imputed" means filled in.
  VP-2.4 fills in charts only; a projection that does not project a player is
  null and left out (`value_reference.row_value`; readout: Jonah Coleman,
  Razzball missing, average of two). The posts describe the code. If Jeremy
  means projections should be filled in, that is a new rule for him to
  approve; if "imputed" means projected points turned into value, the posts
  already say that. **Decided.** Jeremy, 2026-10-29, asked whether
  "imputed" meant projected points turned into value (A) or filling in
  missing projections (B): "A". No new fill-in rule; the posts stand as
  written.
