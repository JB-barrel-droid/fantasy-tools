# Spreadsheet-Driven Review Workbench — Design Spec

The workbench is the human layer over the semantic views. The user is very good
at spreadsheets; the workbench should feel like a workbook, not a database
client. Each "tab" maps to one of the views in `../sql/views/`.

Views (all in `~/workspace/football-signal/sql/views/`):
- `v_props_enriched.sql` — every odds row with player/game/team/book context
- `v_player_week_projections.sql` — latest snapshot per player/game/source/format
- `v_latest_signals.sql` — one row per player/game: Vegas vs expert, deltas,
  ranks, post-worthiness flag, actuals, queue status

## Tabs

### 1. Review Queue (EDITABLE: status + scheduled_for)
Source: `v_latest_signals` WHERE post_worthy = true AND game not started,
ordered by ABS(pts_delta_ppr) DESC.
Columns shown: player, pos, team, matchup, lean, vegas_ppr, expert_ppr,
pts_delta_ppr, vegas_rank, ecr_rank, rank_gap, queue_status, queue_post_type.
The human job: flip queue rows draft → approved (or rejected), set
`scheduled_for`. Writes go to `post_queue.status` / `post_queue.scheduled_for`
only — never to the signal columns. A "needs review" filter =
post_worthy AND queue_status IS NULL (signal fired, no draft written yet —
draft text is generated by the engine, not typed by hand).

### 2. Signal Detail (READ-ONLY)
Source: `v_latest_signals` filtered to one player/game.
Shows all three scoring formats side by side (std / half / full PPR), both
snapshot timestamps (this is where staleness is visible: a 3-day-old ECR
against a 20-minute-old Vegas line), the vintage notes, and — after the game —
actual_std/half/ppr next to the projections. This tab answers "why did we
post this?" and later "was it right?".

### 3. Calibration Scoreboard (READ-ONLY)
Source: `v_latest_signals` WHERE game_status = 'final' AND actuals present.
Aggregates per expert_source and position: mean absolute error and bias
(projected − actual) for vegas vs expert, plus hit rate on the lean
(sign of pts_delta_ppr vs sign of actual − midpoint). This is the raw material
for the weekly scorecard posts and the January track record. Nothing here is
editable; it is the audit trail.

### 4. Props Explorer (READ-ONLY)
Source: `v_props_enriched`, default filter week = current, ordered by
recorded_at DESC. Lets the user eyeball raw market data (line moves, book
disagreements) without SQL. Useful when a signal looks odd — check whether
the underlying props moved.

### 5. Quota & Health (READ-ONLY, refreshed by the collector)
Not a DB view — a small status panel fed by the collector's quota file and
row counts: credits remaining / used this month, rows ingested per snapshot,
snapshot cadence vs plan, any dedupe skips or failures. The user watches the
budget here; the collector enforces it.

## The draft → approved → posted flow
1. Engine computes signals → writes drafts to `post_queue` (status='draft').
2. Human reviews in the Review Queue tab → sets status='approved' (or
   'rejected' with a note) and optionally `scheduled_for`.
3. Poster (manual in Phase 0, automated later) picks up approved rows →
   status='posted', fills `platform_post_id` and `posted_at`.
4. Scorecard pass: after games go final, the Calibration Scoreboard grades
   every posted signal; scorecard drafts are generated the same way.

Statuses are append-only in spirit: never delete a row, move it to
rejected/posted/failed so the audit trail survives.

## Read-only vs editable
- READ-ONLY: every signal/projection/actuals column, all of tabs 2–5.
- EDITABLE: `post_queue.status`, `post_queue.scheduled_for`, `post_queue.note`
  (reviewer annotations only). The workbench must refuse writes to any view
  column that isn't one of these three.

## Build notes
- Ship as a web artifact reading the views through the Supabase REST API
  (views are queryable via PostgREST like tables).
- The `v_latest_signals` queue join parses `post_queue.note`; when a real
  signals table exists, rebuild the view and drop the parser — the workbench
  tabs don't change.
- Filters the user will want on day one: week selector, position filter,
  lean filter (vegas_high / experts_high), post_worthy-only toggle, and
  "hide already-queued".
