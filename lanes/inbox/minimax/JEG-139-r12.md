## Implementation Details

### Four Required Checklist Items

1. **Guard ID**: Unique identifier (e.g., `check_fidelity_ordering`)
2. **Concrete Broken Scenario**: Specific, reproducible defect condition
3. **Broken-State Test + Observed Result**: Command showing guard catching defect
4. **Correct-State Test + Observed Result**: Command showing guard passing

### Applicability Detection

The checker identifies guard-related changes by pattern matching on:
- `pipelines/check_*.py`
- `pipelines/*_guard*.py`
- `tools/guard*.mjs`
- `.github/workflows/*.yml`

Non-guard changes can pass with an explicit applicability declaration (e.g., "docs-only change").

### Placeholder Detection

Content is rejected if it matches:
- Empty or whitespace only
- "TBD", "TODO"
- Markdown placeholders like `<describe here>`
- Just dashes or underscores
