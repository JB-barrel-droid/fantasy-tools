## Implementation Details

### measure_scheduler_slip.py

**Acceptance Criteria Coverage:**

1. **Proposed offline CLI** - `python3 pipelines/measure_scheduler_slip.py --history <json> --output <json>`
   - Implemented with argparse for history JSON input and JSON output
   - Computes nonnegative `started_at - intended cron_at` for scheduled runs only
   - Excludes manual/push runs and missing/ambiguous scheduling evidence
   - UTC timezone used throughout

2. **Fresh valid measurement** - Uses bounded-history maximum (10 runs)
   - Absent/invalid/future/stale (>30d) measurement uses 360-minute fallback
   - Exactly 30d is NOT stale (boundary test included)
   - Visible reason in `slip_reason` field

3. **Deadline calculation** - `deadline + base_grace + slip exactly once`
   - `calculate_effective_deadline()` function implements this
   - Deterministic tests at deadline+360m and +24h demonstrate within-grace vs missed

4. **Scheduled workflow emission** - Each workflow emits:
   - `intended_cron_at` (calculated from cron expression)
   - `actual_started_at` (from run data)
   - `run_id` and `event` for traceability
   - Ambiguous cron attribution returns None, not fabricated

5. **Monitor integration** - Output includes:
   - `workflows` dict with per-workflow measurements
   - `sources` dict with source-level slip (mapped from workflows)
   - `measurement_details` with observation interval, sample counts

6. **JSON state output** - Unit tests assert JSON state, not CLI exit codes
